# AI-Recruiter
Система для автоматического анализа резюме и генерации вакансий с использованием ИИ.

## Контрольный пример · 60%

Из корня проекта в PowerShell. Если окружение `.venv` уже установлено, достаточно последних двух строк.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
$env:RECRUITER_DEMO = '1'
.\.venv\Scripts\python.exe -m uvicorn server.main:app --host 127.0.0.1 --port 8765
```

Откройте [Swagger UI](http://127.0.0.1:8765/docs). В разделе «Контрольный анализ» выберите `POST /api/demo/analyses`, нажмите **Try it out** и отправьте JSON.

```json
{
  "vacancy_text": "Ищем Python-разработчика. Нужен опыт разработки API, Docker будет плюсом.",
  "criteria": [
    {"id": "c1", "text": "знает Python", "required": true, "weight": 2},
    {"id": "c2", "text": "разрабатывал API на FastAPI", "required": true, "weight": 2},
    {"id": "c3", "text": "работал с Docker", "required": false, "weight": 1}
  ],
  "resume_text": "Год писал на Python. Прошёл учебный курс по FastAPI"
}
```

Ответ `201 Created` содержит `analysis_id` (UUID), `score_percent` (число 60), `criteria_results`, `unconfirmed_required`, а также `matches`, `gaps`, `questions` и `summary`. Скопируйте `analysis_id`, остановите сервер через **Ctrl+C** и запустите той же командой с той же базой. В Swagger отправьте `GET /api/demo/analyses/{analysis_id}` с этим ID. Ответ `200 OK` должен вернуть тот же объект. По умолчанию файл базы находится в `data/recruiter.sqlite3`.

### Контракт для Дани и Марка

- Сайт отправляет три поля из примера как `application/json`. Все критерии в запросе считаются подтверждёнными HR. `id` уникален в запросе. `required` принимает JSON-значение `true` или `false`. Если опустить `weight`, сервер подставит 2 при `required: true` и 1 при `required: false`. Допустимы целые веса от 1 до 5.
- Модуль Марка получает критерии и текст резюме. Возвращает `criteria_results` с одним объектом на критерий. В каждом объекте есть `criterion_id`, `status`, `reason` и `quote`. Для `confirmed` и `partial` нужна непустая точная цитата из текста. Для `unconfirmed` поле `quote` равно `null`. На верхнем уровне также нужны массивы строк `matches`, `gaps`, `questions` и строка `summary`.
- Ответ также содержит `criteria` с применёнными весами. Сайт связывает результаты с ними по `criterion_id` после отправки запроса и при повторном открытии. Порядок результатов соответствует порядку запроса. `unconfirmed_required` содержит объекты критериев с `required: true` и статусом `unconfirmed`. Частичное подтверждение видно в `criteria_results`. В контрольном примере `unconfirmed_required` пуст.
- Ошибки приходят в поле `detail`. Статус `422` означает неверный ввод (в том числе пустой список, повтор ID или данные вне контрольного примера), `404` — сохранённый анализ с данным UUID отсутствует, `502` — ответ модуля ИИ не прошёл проверку. При ошибке процент отсутствует. Для проверок схемы запроса FastAPI возвращает массив в `detail`, для остальных перечисленных ошибок — строку. Существующий `Api.send` во Flutter умеет отображать оба формата.
- Маршруты доступны только при `RECRUITER_DEMO=1`, без входа, для локальной проверки с вымышленными данными. Контрольная заглушка ожидает формулировки и текст резюме из примера. Текст вакансии, обязательность и веса можно менять. Текущий Flutter-клиент отправляет запросы на тот же адрес, с которого загружена страница.
